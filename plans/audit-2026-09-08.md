## Confirmed Baseline Findings

- The scheduled refresh is configured for every 30 minutes, but the 12 most
  recent actual runs have gaps of several hours. Scheduled Actions alone is not
  a promise of a 30-minute freshness ceiling.
- Production has no `WORKIE_GH_TOKEN`; the hosted button cannot dispatch a run
  immediately and depends on the next scheduled run.
- `refresh_requests` has no completed state. Run `34190831847` reclaimed request
  `1`, originally requested on August 24, 2026, and completed it again.
- `scripts/claim-refresh.ts` ignores the child cycle's nonzero exit status after
  claiming a request. A failed cycle can appear green in Actions.
- `scripts/refresh.sh` does not propagate enrichment failure.
- GitHub Actions has only the two Turso secrets. Careerjet and Jooble are
  configured on Vercel, where collection does not run, and are skipped by the
  actual cloud collector.
- The board limits every result to 200 rows without pagination. Some jobs cannot
  be reached by further narrowing categorical filters.
- The recency filter uses the source posting date while sorting and the visible
  `seen` value use the effective first-seen date.

## Boundaries

The existing engineering seniority ceiling and Design location policy remain
in scope as intentional eligibility rules, not accidental source loss.
LinkedIn, Indeed, Glassdoor, ZipRecruiter and Handshake remain manual. Explicit
robots exclusions must not be bypassed. An HTTP refusal is not proof a vacancy
is closed. No audit can prove coverage of every job on the internet; the final
report must enumerate reachable sources and verified limits instead.

Only GitHub Actions may publish the corpus. Local audit fixtures and snapshots
must never be mirrored over the hosted database. Secrets are not audit output.

## Additional Fixes Verified Locally

- Preserve employer descriptions and structured fields when a lower-priority
  syndicator refreshes alone; source priority cannot be downgraded by a repeated URL.
- Preserve meaningful title specializations and distinct native requisition IDs.
  Live Anduril examples: Electrical Engineer (Actuators), ID 5186581007, and
  Electrical Engineer (Motor Controls), ID 5186566007. Historical merged source
  rows can separate on ingest without assigning one requisition the other's body.
- Add source-URL and publisher-ID lookup indexes.
- Never publish or cache a partially downloaded cold bootstrap. Rerun cache
  keys include the attempt, so an old workflow rerun does not select an old exact cache.
- Carry request deadlines through response-body reads and check destination
  robots rules after redirects. Unreachable robots files do not authorize crawling.
- Preserve EUR/GBP salary symbols; do not present benefits as wages.
- Keep explicit onsite/hybrid work from being overridden by a stale remote flag.
- Fix queue-plus-current-draft batch overflow and correlate email failures by
  message index, including repeated recipient addresses. No additional real
  outreach messages were sent during this audit.
- Recheck and restore verified-live postings previously delisted by linkcheck,
  without restoring ghost delistings or changing already-dead timestamps.
- Add CI tests, typechecking, lint and build checks on main pushes and pull requests.
